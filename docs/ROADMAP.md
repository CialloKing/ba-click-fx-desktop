## 当前状态与边界

- 当前版本 0.2.18：保留双语、快捷键、特效预设、更新检查和运行诊断，并改进显示状态刷新及模块维护入口。
- Host 是运行时配置的唯一写入者；主配置保持 schema 20，特效预设只保存 `effects`。
- 默认背景感知路径保持既有 WGC 排除与 FX-only 回退。录屏兼容仍是用户主动选择的测试模式；
  OS build `>= 26300` 只代表满足版本门槛，实际能力、Session-local 排除和外部录屏结果仍需验证。
- HDR 与 Active-FX ROI 默认关闭。完整 Bloom 金字塔和局部 Present 已实现，但不能据此声明
  整机性能、功耗或输入延迟收益。
- 普通版本继续执行 Full/Slim 构建、测试、SDK 兼容检查、Full 四资产打包和远端复核。
  未完成的专项硬件矩阵限制对应支持声明，不阻塞无相关声明的普通版本；Slim 不上传预编译资产。

## 本轮维护整理

本轮按职责拆分实现并复用已有测试，不改变产品配置与渲染行为：

- 控制中心布局、显示状态与逐屏策略分别进入独立实现文件；应用和界面测试链接同一实现库，
  共用源码清单、依赖和 Full/Slim 编译定义。
- Host 的启动选项和逐帧性能样本转换移出主文件；聚合、日志写入与渲染循环仍分别负责各自工作。
- Host 控制面与桌面运行时公共实现改为共享构建目标；显示运行时快照组装、输出协商诊断移出主文件，
  状态所有权和发布顺序保持不变。
- 副显示器捕获、恢复与渲染独立成模块；主副显示器复用视觉配置映射和有限输出重试预算，
  Host 的 WGC 重试身份、待处理状态与观测标志集中维护。
- 滑块绑定与页面控件采用统一描述表；特效字段注册复用允许字段、补丁分派和 JSON 输出。
- 显示页的状态读取与解析在单个后台线程执行，合并重复请求并丢弃失效结果；完整刷新保留
  Host 版本与配置代次校验。配置写入等操作仍采用原有同步流程。
- Windows CI 增加现有自动测试与文档检查，保留 WARP 检查，排除真实桌面/硬件验收，并归档失败日志。
- 历史优先级、旧版本过程及原始失败结论归档；后续只在本页维护待办及完成条件。
- 文档检查覆盖当前路线图并自动发现历史快照，检查相对链接与标题锚点。

代码入口、快速验证命令和 CI 范围见[开发指南](DEVELOPMENT.md#维护入口与自动测试)。
后续拆分应跟随实际修改的职责进行，不为缩短文件而增加转发层或改变状态所有权。

### 输入与渲染基线

现有渲染配对基线关闭了 Raw Input；它能用于分析渲染成本，不能作为完整输入延迟基线。
继续使用[现有采集入口](history/ROADMAP_2026-09-16.md#p0输入渲染与-present-延迟诊断)，
分别覆盖 FX-only 与默认背景感知模式，并要求真实输入报告通过 `--require-supported`。
`Input-to-Present-return` 不等于 DWM、扫描输出或物理上屏延迟。

### ROI 性能验收

- 保留 0.2.6 与旧 schema 0.2.7 矩阵的原始 `FAIL`，不追溯改判。
- 新的 4K 170 Hz SDR、schema 4 硬件晋级仍为 `Not Run`；证据必须符合预注册显示规格。
- 同时核对最终像素、GPU 阶段耗时、FPS、查询健康状态与实际局部路径覆盖，不能只报告像素面积。
- 默认背景感知的 Differential Bloom ROI 是独立实验，仅在上述晋级通过后启动，
  并另行验证 WGC 与背景代次；现有背景感知、Spout2 和录制重建继续建立完整输出。

具体门槛和历史数据以[ROI 验证合同](VALIDATION.md#52-active-fx-roi-v027-专用硬件晋级门)为准。

### 视觉回归

使用相同 viewport、配置、输入轨迹和背景，核对点击 `50/100/120/250/450 ms` 时间片，
以及拖拽的按下、保持、释放与释放后寿命。比较圆环、粒子包络、径向能量、拖尾几何/材质和 Bloom。
以 Unity/游戏证据作为视觉真值；随机流尚未等价的部分使用统计与包络比较，避免误报随机布局差异。

### 实机验收

以下项目仍需对应真实环境；代码完成、编译通过或 WARP 结果不替代实机证据：

- Session-local WGC 达到 `Available + Passed`，并验证外部录屏/OBS 的实际录制结果。
- 打包身份的权限允许/拒绝、无边框捕获、安装中断与恢复。
- HDR/Advanced Color 与 SDR 回退，多显示器、混合 DPI/刷新率、跨适配器、热插拔和 device lost。
- 模式切换、长期运行、压力与功耗。

仍缺证据的能力保持测试状态或收窄支持声明，相关 ADR 保持 `Proposed`。

## 执行规则

- 每项小工作独立中文提交，优先复用已有代码和测试。
- 构建、测试和外部采集设置硬超时；失败后先定位原因，不盲目重复。
- 性能修改提供同场景前后对比；视觉修改提供固定时间片回归结果。
- 更新状态时链接实际证据；历史记录保留生成时的合同与结论。
